## 2. 阶段一：数据生成与高斯密度

### 2.1 任务 1.1 `make_synthetic_data`

在 `code/data_gen.py` 中实现：

```python
def make_synthetic_data(means, covs, weights=None, n_samples=1500, seed=0):
    """按混合高斯模型生成数据。

    返回
    ----
    X : (n_samples, D) float64
    y : (n_samples,) int64      真实分量编号，取值 0..K-1
    """
```

实现要点：用 `np.random.default_rng(seed)` 建立随机数发生器；用 `rng.choice(K, size=n_samples, p=weights)` 抽分量指示 $z_n$；再按分量分组，用 `rng.multivariate_normal` 批量抽取。注意每个样本必须用**自己的**那个分量的均值和协方差，最直接的写法是按 $k$ 循环、一次性抽该分量的全部样本并填入对应位置，而不是在 Python 里逐样本循环。

验收标准：对三个分离良好的簇，用 `np.bincount(y)` 检查样本比例是否接近设定的 $\pi_k$；用 `X[y==k].mean(axis=0)` 和 `np.cov` 检查经验均值、经验协方差是否接近设定值（样本量 1500 时误差应在百分之几量级）。

### 2.2 任务 1.2 `normal_logpdf`

在 `code/data_gen.py`（或另建 `gaussian.py`）中实现：

```python
def normal_logpdf(X, mean, cov, reg=1e-6):
    """多元高斯对数密度，X 为 (N, D)。"""
```

实现要点：加 `reg`（例如 `1e-6 * np.trace(cov) / D`）到协方差对角线，做 Cholesky 分解 $L$，用对数行列式公式 $\ln\lvert\Sigma\rvert=2\sum_d\ln L_{dd}$ 和马氏距离的三角求解形式，返回形状 `(N,)` 的对数密度数组。中间不要出现 `np.linalg.inv` 和 `np.linalg.det`。

验收标准：标准正态 $\mathcal N(0,1)$ 在 $x=0$ 处的对数密度应等于 $-\frac12\ln(2\pi)\approx-0.9189$；二维各向同性高斯 $\Sigma=\sigma^2I$ 的结果应与逐元素手算的 $-\ln(2\pi\sigma^2)-\frac{\lVert x-\mu\rVert^2}{2\sigma^2}$ 在随机点集上一致（容差 $10^{-10}$）。再取一个强相关的协方差（如 `[[1, 0.99], [0.99, 1]]`），确认没有出现 `nan` 或 `-inf`。

### 2.3 本次使用的合成数据集

按实验要求"用高斯分布产生 $k$ 个高斯分布的数据（不同均值和方差）"，用下面这组参数，它同时覆盖了各向同性、细长、倾斜三种协方差形态：

```python
TRUE_MEANS = np.array([[-4.0, -3.0],
                       [ 0.0,  4.5],
                       [ 5.0, -2.0]])
TRUE_COVS  = np.array([[[1.0, 0.0], [0.0, 1.0]],          # 各向同性，圆
                       [[2.5, 0.0], [0.0, 0.25]],         # 细长，横躺
                       [[1.2, 0.9], [0.9, 1.2]]])         # 倾斜椭球
TRUE_WEIGHTS = np.array([0.4, 0.35, 0.25])
```

这三个簇互相分离但协方差形态差异明显：k-means 会倾向于按距离把第二个簇切得不好（它的长轴方向与簇间连线不垂直），而 GMM 应该能恢复出椭圆的朝向。这个差异就是第 4 节要观察的核心现象。

这里有一个贯穿全实验、必须提前讲清楚的问题：**有限样本下"经验统计量"与"设定值"不相等**。用 `seed=0`、`n_samples=1500` 生成一次，按真实分量编号分组统计，得到的是下面这组数字（运行 `python data_gen.py` 会打印同样的对照）：

| 统计量 | 设定值 | 本次样本的经验值 | 偏差 |
|---|---|---|---|
| 均值（最大绝对偏差） | `TRUE_MEANS` | 见程序输出 | 0.079 |
| 混合比例 | [0.400, 0.350, 0.250] | [0.391, 0.343, 0.266] | 0.016 |
| 协方差（最大绝对偏差） | `TRUE_COVS` | — | 0.060 |
| 协方差长短轴比（分量 1） | 10.0 | 10.63 | 0.63 |

偏差的来源是抽样波动，生成样本数越多偏差越小（量级为 $1/\sqrt{N_k}$）。这件事直接影响验收方式：EM 求的是**这份样本**的最大似然解，它的正确性应当用"是否等于经验统计量"来衡量，而不是"是否等于设定值"。第 4.4 节给出了具体的两层验收方案。实验报告里也应当把这三列都列出来，才能说明"EM 恢复了正确结果"这句话到底在什么意义上成立。

## 3. 阶段二：k-means

### 3.1 任务 2.1 `assign_clusters`

```python
def assign_clusters(X, centroids):
    """返回每个样本最近的簇编号 (N,)。"""
```

实现要点：用广播一次算出 $(N,K)$ 的距离矩阵，再沿 $K$ 方向取 `argmin`。距离平方可写成 $\lVert x\rVert^2-2x^{\mathsf T}\mu+\lVert\mu\rVert^2$，但用 `X[:, None, :] - centroids[None, :, :]` 直接算差再 `np.sum(d**2, axis=2)` 更不容易出错，内存也够用（$N=1500,K=3$）。

验收标准：手工构造 $X=[[0,0],[1,1],[10,10]]$、`centroids=[[0,0],[10,10]]`，结果应为 `[0,1,1]`。

### 3.2 任务 2.2 `compute_inertia`

```python
def compute_inertia(X, labels, centroids):
    """返回簇内平方和 J = sum_n ||x_n - mu_{label_n}||^2。"""
```

验收标准：单簇情形（所有点归到 0 号簇）的 $J$ 应等于全体样本对均值的离差平方和 `np.sum((X - X.mean(0))**2)`。

### 3.3 任务 2.3 `kmeans`

```python
def kmeans(X, k, max_iter=100, tol=1e-6, seed=0):
    """Lloyd 算法。

    返回
    ----
    centroids : (k, D)
    labels    : (N,)
    inertia   : float
    history   : list[dict]   每轮的 {'iter', 'inertia', 'shift'}
    """
```

实现要点：先随机从样本中选 $k$ 个不同的点作初始中心（用 `rng.choice(N, size=k, replace=False)`）。主循环里先分配、再更新、再算中心位移 `shift = np.linalg.norm(new - old, axis=1).max()`，把 `inertia` 和 `shift` 记进 `history`，当 `shift < tol` 或达到 `max_iter` 时退出。**每轮都要记录 inertia**，因为第 4 节要画它的下降曲线并验证单调性。

空簇处理：更新中心时用 `np.bincount(labels, minlength=k)` 统计每簇样本数，若某簇计数为 0，说明该中心在此轮没有分到样本，不要让它变成 `nan`。简单做法是保留旧中心并在 `history` 里记一个标记，稍后在报告里说明遇到了几次。

验收标准（三个都要过）：

1. `inertia` 序列单调不增；
2. `seed=0` 时最终 `labels` 与真实 `y` 在最优排列匹配下的准确率为 1.0000（用 `metrics.best_match_accuracy`），实测迭代 5 轮、$J=3570.5$。注意这里只用 `seed=0` 这个"好种子"作硬指标，因为下一个标准说明单次运行本来就不可靠；
3. 同一份数据跑 `seed=0..9`，各次 `inertia` 存在明显差异。实测结果是 10 次里有 1 次（`seed=3`）掉进了糟糕的局部最优：$J=18063.7$，准确率只有 0.539，其余 9 次都是 $J=3570.5$。这个 5 倍差距是"k-means 单次运行不可靠、必须多次重启"的直接证据，报告里应当保留这组数字。

这里给一个额外要求：把 `seed=0..9` 的各次 `inertia` 和准确率保存下来（后面第 6.3 节要求落盘），因为这是报告中最有说服力的一组实验结果之一。

### 3.4 任务 2.4 `kmeans_restarts`

```python
def kmeans_restarts(X, k, n_init=10, **kwargs):
    """多次随机重启，返回 inertia 最小的那次结果。"""
```

实现要点：循环调用 `kmeans`，比较 `inertia`，保留最优的 `centroids`、`labels`、`history`，另外返回全部 `n_init` 次的 inertia 列表以便报告里写"多次重启把 J 从多少降到多少"。这是实际工程里必做的一步，也是理解 k-means 局部最优问题的直接证据。注意 `kmeans` 的 `seed` 参数要通过 `kwargs` 逐个传入不同的值（`for s in range(n_init): kmeans(X, k, seed=s, **kwargs)`），否则十次重启会得到同一个结果，重启就白做了。

验收标准：`kmeans_restarts(X, 3, n_init=10)` 返回的 `inertia` 应当等于 3570.5，准确率 1.0，而 `all_inertias` 中最大值 18063.7。

## 4. 阶段三：GMM 与 EM 算法

`code/gmm.py` 里的函数自上而下依次依赖，建议按下面的顺序写，每写一个就用上一节的验收标准测一次。

### 4.1 任务 3.1 `estimate_log_gaussian_prob`

```python
def estimate_log_gaussian_prob(X, means, covs):
    """返回 (N, K) 的 log N(x_n | mu_k, Sigma_k)。"""
```

即对每个分量调用任务 1.2 的 `normal_logpdf`，堆成矩阵。验收标准：用手工构造的两分量模型检查第 $k$ 列与单独调用 `normal_logpdf` 的结果一致。

### 4.2 任务 3.2 `estimate_log_resp`（E 步）

```python
def estimate_log_resp(X, weights, means, covs):
    """返回 (N, K) 的 log 责任度矩阵和 (N,) 的逐样本对数似然。"""
```

实现要点（对应原理文档 4.3 和 5.1 节）：先算 `log_prob = estimate_log_gaussian_prob(...)`，加上 `np.log(weights)` 得到 `weighted_log_prob`；用 log-sum-exp 沿 $K$ 方向归一化：

```python
lse = logsumexp(weighted_log_prob, axis=1)      # (N,)
log_resp = weighted_log_prob - lse[:, None]
```

返回的 `lse` 同时就是每个样本的对数似然，累加即为总对数似然。建议自己写一个 `logsumexp(a, axis)` 小函数（减最大值、求和、取对数），十行以内，不要引入 scipy。

验收标准：对任意输入，`np.exp(log_resp).sum(axis=1)` 应全为 1（容差 $10^{-12}$）；用一组随机参数计算的对数似然与"先算密度再取对数、再求和"的朴素写法一致（容差 $10^{-8}$），这一步能验证 log-sum-exp 的实现没错。

### 4.3 任务 3.3 `m_step`（M 步）

```python
def m_step(X, log_resp):
    """由 log 责任度估计新参数，返回 weights, means, covs。"""
```

实现要点（对应原理文档 4.4 节）：先把 `log_resp` 取指数得到 $\gamma_{nk}$，再算有效样本数 `nk = resp.sum(axis=0)`（注意 $\sum_k N_k=N$ 这个恒等式，可以用来做断言）。然后依次计算

$$
\mu_k=\frac{1}{N_k}\sum_n\gamma_{nk}x_n,\qquad
\Sigma_k=\frac{1}{N_k}\sum_n\gamma_{nk}(x_n-\mu_k)(x_n-\mu_k)^{\mathsf T},\qquad
\pi_k=\frac{N_k}{N}
$$

协方差的三重循环写法不可接受，用 `(resp[:, k] * diff.T) @ diff / nk[k]` 这类矩阵乘法一次算完。**注意 $\Sigma_k$ 必须用刚更新过的 $\mu_k$ 计算**，用旧均值是一个隐蔽的错误——它不会让程序崩溃，但会让对数似然在若干轮后开始下降，破坏单调性。

验收标准：把真实标签做 one-hot 当作责任度传入（即硬分配），得到的 `means` 应等于各簇样本均值，`covs` 应等于 `np.cov(X[y==k].T, bias=True)`（`bias=True` 对应除以 $N_k$ 而非 $N_k-1$，这个细节要留意），`weights` 应等于 `np.bincount(y)/N`。

### 4.4 任务 3.4 `gmm_em`（主循环）

```python
def gmm_em(X, k, max_iter=200, tol=1e-6, reg=1e-6, init="kmeans", seed=0):
    """EM 主循环。

    返回
    ----
    params   : dict(weights=(K,), means=(K,D), covs=(K,D,D))
    resp     : (N, K) 最终责任度
    log_lik  : list[float]   每次迭代后的总对数似然
    history  : list[dict]    每轮记录，含 'iter'、'log_lik'、'delta'
    """
```

实现要点：初始化按 `init` 参数分两条路。`"kmeans"` 用任务 2.4 的结果：均值取 k-means 中心，协方差统一取全体数据的协方差（或各簇协方差），权重取 `1/K`；`"random"` 则随机选 $k$ 个样本作均值、协方差取全体协方差、权重 `1/K`，用于第 5 节的对照实验。

主循环每轮做三件事：E 步算 `log_resp` 与总对数似然、记进 `log_lik` 和 `history`、判断相对变化量是否小于 `tol`；未收敛则 M 步更新参数、检查每个分量是否退化（`nk[k]` 过小）、给协方差加 `reg` 正则。**先记似然再判断收敛**，这样 `log_lik` 的长度就等于实际迭代次数，画曲线时横坐标不会错位。

验收标准（本实验最关键的几条）。验证脚本已经跑过一遍，下面的数字都是实测值，可以用作对照：

1. `log_lik` 严格单调不降，逐项检查 `np.diff(log_lik) >= -1e-9` 应全部为真。若为假，按原理文档 4.5 节列出的四个原因逐个排查。
2. **与经验统计量精确一致**。分量编号与真实类别的关系是任意的，先做排列对齐（`resp.argmax(1)` 与真实标签的最佳匹配，或直接枚举 $3!$ 种排列取偏差最小者），再对每个分量比较：估计均值应当等于该簇样本均值，估计协方差应当等于 `np.cov(X[y==k].T, bias=True)`，估计权重应当等于该簇样本比例。实测偏差为 `0.00000`（到双精度极限），这才是 MLE 应该给出的结果。这一步能同时抓出均值、协方差、权重三处的实现错误，比笼统地"和设定值比一下"有效得多。
3. **用对数似然做交叉验证**。把设定值直接代入似然函数，得到的结果应当低于估计参数的结果。实测：估计参数 $-5671.2374$，设定真值 $-5677.7842$。真值反而更差，说明 EM 找到的确实是这份样本上的最大似然解；如果反过来（设定值的似然更高），说明 EM 卡在了局部最优或实现有误。
4. 协方差形态在排列对齐后应当被恢复：分量 1 的经验长短轴比 10.63（设定 10.0，横躺），分量 2 为 6.96（设定 7.0，主轴约 45 度倾斜），分量 0 为 1.10（设定 1.0，接近各向同性）。用 `np.linalg.eigh` 检查特征值之比与主轴方向。
5. 把 `k` 设成 2 或 4 再跑，实测 $k=2$ 时对数似然降到 $-6846.9$，$k=4$ 时升到 $-5669.3$（仅比 $k=3$ 高 2 个单位，却多用了大量参数）。这说明"似然更大"不等于"模型更合适"，是模型选择问题的直接体现，值得写进报告。

关于初始化的一点实测结论：本实验的三个簇分离得很好，`init="random"` 连续 10 个种子的最终对数似然**完全相同**（标准差 0.00），说明这个数据集上 EM 不敏感。如果想让"初始化敏感性"这个实验现象显现出来，需要人为制造困难：把簇间距离缩小、或让两个分量的协方差重叠、或增大 $K$。不要因为跑出来"10 次结果一样"就以为代码写错了。

### 4.5 任务 3.5 对数似然的独立校验

EM 主循环内部算出来的对数似然容易自说自话：如果 log-sum-exp 写错、责任度没归一化，曲线仍然可能看起来单调上升。所以要写一个独立函数，用最终参数和"朴素定义"重算一遍：

```python
def compute_log_likelihood(X, weights, means, covs):
    """sum_n log sum_k pi_k N(x_n | mu_k, Sigma_k)，用朴素写法实现。"""
```

验收标准：`abs(gmm_em 返回的最后一个 log_lik - compute_log_likelihood(最终参数)) < 1e-6`。这一条过了，才能确信前面的曲线是真结果。

## 5. 阶段四：评价与可视化

### 5.1 已提供的指标函数（`code/metrics.py`）

`best_match_accuracy(y_true, y_pred)` 枚举 $K!$ 种标签排列取最高准确率，并返回最优映射；`adjusted_rand_index(y_true, y_pred)` 计算 ARI，无需排列匹配；`cluster_purity`、`silhouette_score` 用于无标签情形的内部评价；`confusion_matrix_from_match` 输出匹配后的混淆矩阵。

### 5.2 已提供的绘图函数（`code/viz.py`）

`plot_clusters` 画散点加中心；`plot_gmm_ellipses` 用协方差矩阵的特征分解画马氏距离为常数的椭圆（$1\sigma$、$2\sigma$ 两圈），这是把协方差矩阵"看见"的关键工具；`plot_curve` 画任意随迭代变化的曲线；`plot_convergence_compare` 把多种初始化的对数似然曲线画在同一张图上。

椭圆的画法值得说明：对二维高斯，协方差 $\Sigma=U\Lambda U^{\mathsf T}$，取单位圆上参数化点 $t\mapsto (r\sqrt{\lambda_1}\cos t,\ r\sqrt{\lambda_2}\sin t)$，再经 $U$ 旋转、加均值平移即得。半径 $r$ 取 1 和 2 分别对应 $1\sigma$ 与 $2\sigma$ 等高线。

### 5.3 要产出的图

实验要求"测试效果"和"看看每次迭代后似然值变化情况"，对应下面四张必出的图。第一张是合成数据的真实分布，画散点并按真实标签着色，叠加真实协方差椭圆，作为"标准答案"；第二张是 k-means 结果，画归属着色与最终中心，并附不同 `seed` 下的 inertia 柱状对比；第三张是 GMM 结果，画软归属着色（可按最大责任度着色，用透明度表示归属强度）加估计的协方差椭圆，与第一张并排看；第四张是对数似然曲线，横轴为迭代次数，纵轴为对数似然，同时画出 k-means 的 inertia 曲线（归一化后）以便比较两者的收敛速度，并在图上标注收敛所需的迭代次数。

### 5.4 参数恢复对照表

实验要求"考察 EM 算法是否可以获得正确的结果（与你设定的结果比较）"，所以要把 $\pi_k,\mu_k,\Sigma_k$ 三项做成表格：设定值、估计值、偏差，均值与混合系数逐项列，协方差用行列式、迹、特征值比这些标量来概括（矩阵本身列进表格会很难读，完整矩阵放到附录或单独输出到文本文件）。同时记录"达到参数误差阈值所需迭代次数"和"总迭代次数"，这两个数能说明 EM 的收敛速度。

## 6. 阶段五：应用到 UCI 数据集

### 6.1 数据读取

两个数据集已经放在 `data/` 下，格式不同，各写一个加载函数。`iris.data` 是逗号分隔，四列数值加一列类别名（`Iris-setosa`、`Iris-versicolor`、`Iris-virginica`），文件末尾有一个空行要跳过。`seeds.data` 是制表符分隔，前七列是特征（面积、周长、紧致度、籽粒长度、籽粒宽度、偏度系数、紧致度系数的谷维数），最后一列是 `1/2/3` 的类别编号。

需要注意的是两个数据集的量纲问题。Iris 的四个特征数值范围相近（0.1 到 7.9），可以不标准化；Seeds 的七列量纲差别很大（面积约 10–21，紧致度约 0.8–0.92），直接把原始数值送进欧氏距离会让面积一列主导整个聚类。所以加载函数里要做 **z-score 标准化**（按列减均值除标准差），并且标准化统计量只在全体数据上算一次。要额外提醒的是：Iris 的花瓣长度与花瓣宽度高度相关，协方差矩阵接近奇异，这正是检验协方差正则化是否起作用的场合。

### 6.2 实验设计

每个数据集上跑四组对比，构成实验报告的主体内容。第一组是 k-means 与 GMM 的 ARI 对比，前者硬分配、后者软分配，看软分配是否带来提升。第二组是同一数据集上不同 $K$（真实类别数为 3，另跑 $K=2,4$）的对数似然和 BIC，观察 BIC 是否选中正确的 $K$。第三组是不同初始化的稳定性：`init="random"` 与 `init="kmeans"` 各跑 10 次，比较最终对数似然的均值和标准差，这直接量化了 EM 对初始化的敏感程度。第四组是维度选择：Iris 用全部四维和只用花瓣长宽两维各跑一次，两维情形可以画出协方差椭圆，四维情形只能看指标。

参考实现跑出的结果如下，可以作为对照基准：

| 数据集 | 方法 | ARI | 准确率 | 对数似然 | 迭代次数 |
|---|---|---|---|---|---|
| Iris 花瓣两维 | k-means | 0.8510 | 0.9467 | — | 5 |
| Iris 花瓣两维 | GMM | 0.9222 | 0.9733 | −136.6 | 27 |
| Iris 全部四维 | k-means | 0.7302 | 0.8933 | — | 5 |
| Iris 全部四维 | GMM | 0.9039 | 0.9667 | −181.0 | 22 |
| Seeds 七维（标准化） | k-means | 0.7733 | 0.9190 | — | 3 |
| Seeds 七维（标准化） | GMM | 0.8123 | 0.9333 | 302.5 | 14 |
| Seeds 两维（面积+偏度） | k-means | 0.6091 | 0.8476 | — | 4 |
| Seeds 两维（面积+偏度） | GMM | 0.6174 | 0.8476 | −530.6 | 69 |

这组数字里有几个值得分析的规律。GMM 在四组里全部不差于 k-means，其中 Iris 四维的提升最明显（0.73 提到 0.90），说明真实数据里确实存在非球形、大小不一的簇，硬分配的球假设代价很大。Iris 四维反而不如花瓣两维，因为多出来的萼片特征对 versicolor/virginica 的区分帮助有限，反而稀释了距离。Seeds 两维的结果明显差于七维，说明那两列特征不足以分离三类。另外 Iris 的收敛迭代次数（22 到 27 轮）显著多于合成数据（5 轮），因为真实数据的簇有重叠，需要更细致的责任度调整。

第三组实验有一个需要提前预判的结果：在分离良好的数据上，`init="random"` 与 `init="kmeans"` 可能给出完全相同的最终对数似然，标准差为 0。这不代表实验失败，恰恰说明 EM 在该数据集上不依赖初始化。要观察敏感性，应该在 Iris 四维（簇有重叠）或人为缩小簇间距的合成数据上做，报告里也应当说明"敏感性依赖数据难度"这个前提，而不是笼统地下结论。

### 6.3 结果记录

每一步的结果都要落盘，不要只打印在终端里（终端内容容易丢）。建议把每次运行的 `K`、初始化方式、`seed`、最终对数似然、迭代次数、ARI、准确率写成一个 CSV 汇总表，把完整参数和逐轮似然写进 JSON，图片存到 `figures/`。这样后面写实验报告时数据是现成的，不需要重跑。

### 7.1 实测性能

纯 NumPy 实现的 EM 在这些数据集上的耗时（`init="random"`，最多 60 轮，单核）：

| 数据集 | N | D | K | 耗时 | 迭代 |
|---|---|---|---|---|---|
| `iris_4d` | 150 | 4 | 3 | < 0.1 s | 60 |
| `wine` | 178 | 13 | 3 | < 0.1 s | 48 |
| `seg_test` | 2100 | 19 | 7 | 0.3 s | 35 |
| `wdbc` | 569 | 30 | 2 | < 0.1 s | 60 |
| `vehicle` | 846 | 18 | 4 | 0.1 s | 60 |
| `satimage` | 6430 | 36 | 6 | 1.9 s | 60 |
| `optdigits`（前 1000 条） | 1000 | 64 | 10 | 0.2 s | 17 |
| `pendigits`（前 2000 条） | 2000 | 16 | 10 | 0.1 s | 31 |

结论是**这些数据集全都能跑**，包括样本量一万多的 `pendigits`：真正决定耗时的是维数 $D$（每次密度计算都要做 $D\times D$ 的分解与三角求解），而不是样本量 $N$（向量化后 $N$ 只是一次矩阵乘法的行数）。所以 `optdigits` 的 64 维比 `pendigits` 的 10992 个样本更贵。用来做"更大数据集"实验，推荐 `pendigits`（样本量维度都合适）和 `optdigits`（维数高，能观察维数效应），`satimage` 则适合观察类别不均衡对混合系数的影响。

### 7.2 数值稳定性：近奇异协方差是真实威胁

在 `seg_test`（19 维，7 类）上跑参考实现时出现了**对数似然不单调**的情况：迭代到第 27 轮达到峰值后开始缓慢下降，最大降幅 3.63。这个现象一开始看起来像实现错误，逐项排查后的结论值得写进报告，因为它涉及一个容易误判的边界。

排查过程如下。先确认 M 步确实是最优的：计算完全数据对数似然的期望 $Q(\theta)$，每一步 $Q$ 都在上升（这一步排除了 M 步公式错误）。再确认 E 步的责任度归一化无误（行和与 1 的偏差为 $10^{-15}$）。然后用两种独立的密度算法交叉验证：Cholesky 分解路径与特征分解路径，两者的 $\ln|\Sigma|$ 一致到 $10^{-9}$，逐点马氏距离一致到 $10^{-12}$。最后发现原因在于**协方差矩阵的条件数**：这些分量的条件数达到 $10^{7}$，而数据规模一大，对数似然的绝对值也大（$9\times10^4$），浮点表示的相对精度 $10^{-16}$ 乘以条件数放大后，落到对数似然上就是几个单位的波动量级。

这是一个需要正确解读的现象。EM 的单调性定理在精确算术下成立，实际计算中受到条件数放大时会出现微小回落；判据应当用相对量而不是绝对量：

```python
d = np.diff(log_lik)
tol = np.abs(np.array(log_lik[:-1])) * 1e-12    # 相对判据
monotone = bool(np.all(d >= -tol))              # 而不是 np.all(d >= -1e-9)
```

同时这也给出了协方差正则化的真正理由。本实验用的 $\epsilon=10^{-6}\cdot\mathrm{tr}(\Sigma)/D$ 对合成数据（条件数约 $10^2$）绰绰有余，但在 19 维、7 个分量的真实数据上，条件数被推到了 $10^7$，说明这个 $\epsilon$ 偏小。如果想让对数似然曲线干净单调，可以把 $\epsilon$ 提到 $10^{-4}$ 量级，代价是略微偏离最大似然解——这时应明确说明你优化的是带惩罚的目标（正则化 EM 对应参数上的先验，即 MAP 估计），而不是纯 ML。

另外要留意正则化的作用目标。EM 保证单调上升针对的是**不带惩罚**的对数似然，而 M 步里加 $\epsilon I$ 相当于换了一个带惩罚的目标，所以在原理上就不应该期待它严格单调。实测中不加正则化时 $Q$ 明显更高（第 8 轮 96641 对 91942），这也说明 $\epsilon$ 不宜过大。稳妥的做法是只在必要时加：先尝试 Cholesky 分解，失败了再补 $\epsilon$，而不是每轮无条件施加。

### 7.3 高维时的另一个陷阱

用 `optdigits` 这类高维数据时要小心广播。密度计算里若写

```python
diff = X[:, None, :] - means[None, :, :]     # (N, K, D) —— 这个还行
```

在 `N=5620, K=10, D=64` 时是 0.03 GB，没问题。但若在协方差层面写成 `(N, K, D, D)`（例如对每个样本每个分量构造完整协方差再求逆），规模会变成 $D^2$ 倍，`N=5620, K=10, D=64` 直接需要 18 GB 以上，必然崩。正确的做法是：**协方差永远按分量处理**（$K$ 个 $D\times D$ 矩阵），样本维度只在马氏距离这一步以矩阵乘法的方式进入，绝不显式构造 $(N,K,D,D)$。前面给出的实现提示（先 Cholesky 再对 $(D,N)$ 解三角方程）天然满足这一点。

同类的问题出在评价环节。`metrics.silhouette_score` 会构造 $(N,N)$ 的距离矩阵，$N=10992$ 时就是 483 MB 的临时数组（再加上中间量会更大），$N=45312$ 时需要 16 GB。要在 `pendigits` 这个量级上用轮廓系数，必须抽样计算，给 `silhouette_score` 加一个 `sample_size` 参数，随机抽一两千个样本估计即可。

### 7.4 大规模数据上的实测聚类质量

跑得动不等于聚得出东西。把大样本数据集都测一遍（`init="kmeans"`，$K$ 取真实类别数），结果分成三档：

| 数据集 | N | D | K | k-means ARI | GMM ARI | GMM 用时 |
|---|---|---|---|---|---|---|
| `pendigits` | 10992 | 16 | 10 | +0.5005 | **+0.5650** | 3.5 s |
| `satimage` | 6430 | 36 | 6 | +0.4100 | **+0.4641** | 3.1 s |
| `wdbc` | 569 | 30 | 2 | +0.6765 | **+0.7434** | < 0.1 s |
| `vehicle` | 846 | 18 | 4 | +0.1186 | +0.1487 | 0.1 s |
| `letter` | 20000 | 16 | 26 | +0.1284 | +0.1941 | 33.4 s |
| `optdigits` | 5620 | **64** | 10 | +0.5512 | +0.2375 | 6.5 s |
| `electricity` | 45312 | 8 | 2 | +0.0038 | +0.0111 | 0.4 s |

结论很直接：**`pendigits` 是最好的大规模选择**。它样本量一万多、维度适中，实测 $K=10$、`init="kmeans"` 时 61 轮收敛、耗时 3.5 秒、对数似然严格单调（最小增量 $+0.015$）、ARI 0.5650 明显高于 k-means 的 0.5005。`satimage` 次之，且它的类别不均衡（1531:625）可以用来观察混合系数。`letter` 虽然样本量两万，但 26 个类别在 16 维空间里严重重叠，ARI 只有 0.19。

注意上表 `pendigits` 一行的迭代列显示 60，是因为最初那轮测试设了 60 轮上限；放开上限后它 61 轮收敛，说明恰好卡在边界上。这类"看起来没收敛"的情况要先确认是不是被 `max_iter` 截断，再下结论。

有两个数据集的结果特别值得写进报告，因为它们各自推翻了一个常见直觉。

**`optdigits`：维度上去了，GMM 反而输给 k-means。** 64 维、10 个分量、每簇只有 562 个样本，而一个 $64\times64$ 协方差有 $64\times65/2=2080$ 个自由参数，每个分量要估的参数比它拥有的样本还多，协方差矩阵条件数达到 $4.3\times10^7$。结果是 GMM 的 ARI（0.238）低于 k-means（0.551）。加大正则化能提升 ARI，但代价是把似然压垮：

| 正则化系数 $\epsilon$ | GMM ARI | 对数似然 | 协方差最大条件数 |
|---|---|---|---|
| $10^{-6}$（默认） | +0.2375 | 344055.3 | $4.3\times10^7$ |
| $10^{-4}$ | +0.3321 | 158923.1 | $3.6\times10^5$ |
| $10^{-3}$ | +0.5062 | 55682.3 | $2.2\times10^4$ |
| $10^{-2}$ | +0.5402 | **−44301** | $2.2\times10^3$ |

对数似然从 344055 掉到 $-44301$，说明提升 ARI 靠的是把协方差压成接近球形——那正是 k-means 的假设，等于放弃 GMM 的表达能力去换取划分质量。这就是高维下 GMM 的核心困境，也是"每一维都需要足够样本"这一经验法则的具体体现（粗略标准是每个分量的样本数应远大于 $D$，甚至 $D^2$ 量级）。

**`electricity`：样本量最大，却完全没有可聚类的结构。** ARIA 只有 0.0038（k-means）和 0.0111（GMM），而随机划分的 ARI 期望就是 0；准确率 0.53–0.61，而**全部预测为多数类就能得到 0.5755**。45,312 个样本跑完只要 0.4 秒，说明问题不在算力。

原因有两层。第一，这个数据集是时间序列：相邻样本的特征自相关极高（`nswdemand` 的 lag-1 自相关是 0.9784，`transfer` 是 0.9695），每 48 个半小时观测构成一天，实际独立信息量远小于样本数，$N=45312$ 里有大量重复信息。第二，电价涨跌由供需的瞬时波动决定，而特征（价格、需求）在涨和跌两种情形下高度重叠，所以它本质上不是一个聚类问题——论文里它是分类任务，类别由未来的价格变化定义，而不是由当前特征的聚类结构定义。

如果想用这个数据集，合适的用法不是拿它当"更大的聚类数据"，而是**用它做一个反面案例**：样本量增加 20 倍并不能凭空造出簇结构，聚类能否成功取决于数据本身是否存在簇，而不取决于数据有多少。这个结论本身很有价值，但它无法完成"用 GMM 做聚类并取得好效果"这一要求，所以主实验仍应放在 `pendigits` 上。

另外提醒：`electricity` 的 `date` 列在 OpenML 版本里已经被 WEKA 归一化成 0–1 的数值，原始时间戳不存在了，因此做不了基于时间顺序的划分（时间序列不能随机划分训练集测试集）。如果要用它，得从 UCI 取原始版本，或者接受"只用 `day` 与 `period` 两个时间特征"的限制。

用 `optdigits` 这类高维数据时要小心广播。密度计算里若写

```python
diff = X[:, None, :] - means[None, :, :]     # (N, K, D) —— 这个还行
```

在 `N=5620, K=10, D=64` 时是 0.03 GB，没问题。但若在协方差层面写成 `(N, K, D, D)`（例如对每个样本每个分量构造完整协方差再求逆），规模会变成 $D^2$ 倍，`N=5620, K=10, D=64` 直接需要 18 GB 以上，必然崩。正确的做法是：**协方差永远按分量处理**（$K$ 个 $D\times D$ 矩阵），样本维度只在马氏距离这一步以矩阵乘法的方式进入，绝不显式构造 $(N,K,D,D)$。前面给出的实现提示（先 Cholesky 再对 $(D,N)$ 解三角方程）天然满足这一点。

### 7.5 K 扫描与 BIC：模型选择并不听话

在 `pendigits` 上把 $K$ 从 2 扫到 10（`init="kmeans"`，真实类别数是 10）：

| K | ARI | 准确率 | 对数似然 | 迭代 | BIC | 协方差最大条件数 | 严格单调 |
|---|---|---|---|---|---|---|---|
| 2 | +0.1461 | 0.2063 | −141802.7 | 18 | 286443.4 | $4.3\times10^2$ | 是 |
| 3 | +0.2289 | 0.2923 | −114533.3 | 70 | 233328.2 | $4.4\times10^6$ | 否 |
| 5 | +0.3194 | 0.4716 | −74379.6 | 61 | 155868.1 | $7.7\times10^6$ | 否 |
| 10 | +0.5650 | 0.6948 | −17486.4 | 61 | **49200.1** | $7.9\times10^6$ | 是 |

两点值得注意。第一，**ARI 与 BIC 在 $K\le10$ 上同向**：BIC 一路下降、ARI 一路上升，在真实的 $K=10$ 处 BIC 最小。但这个例子里 BIC 选对只是因为真实 $K$ 恰好是扫描区间的右端点，$K>10$ 的情形没测完，不能说 BIC 真的偏好 $K=10$。

第二，**中间 $K$（3 和 5）的对数似然反而不严格单调**，而 $K=2$ 和 $K=10$ 是单调的。这与 7.2 节的解释一致：$K=3$ 和 $K=5$ 时条件数已经升到 $10^6\sim10^7$，而 $K=2$ 时只有 $4\times10^2$（非常良态）。所以"单调性是否成立"跟 $K$ 的选择有关，不能只测一个 $K$ 就断言实现正确。这也再次说明相对判据（$|\Delta L|/|L|$）比绝对判据合适。

作为对照，`optdigits`（64 维，真实 $K=10$）的扫描结果清晰地展示了高维下 BIC 的罚项有多重：

| K | ARI | 对数似然 | BIC | 自由参数个数 | 条件数 |
|---|---|---|---|---|---|
| 2 | +0.0035 | −27967.0 | 92965.6 | 4289 | $1.4\times10^7$ |
| 5 | +0.1655 | 241620.4 | −390648.9 | 10724 | $1.9\times10^7$ |
| 10 | +0.2360 | 344025.5 | **−502858.5** | 21449 | $4.3\times10^7$ |
| 12 | +0.3058 | 357780.1 | −493327.4 | 25739 | $3.4\times10^7$ |

这里 BIC 在 $K=10$ 取到最小值（正确选出了真实类别数），而且与 `pendigits` 不同的是扫描区间延伸到了真实值之上，所以"BIC 选中 10"这个结论是可靠的。原因是 $D=64$ 时每个分量要 2144 个协方差参数，从 $K=10$ 加到 $K=12$ 就多 4290 个参数，$\ln(5620)\approx8.6$ 的罚项放大后足以抵消似然的提升。注意 $K=12$ 的 ARI（0.306）高于 $K=10$（0.236），却因为 BIC 罚项被判为更差的模型——这正是 7.4 节那个困境的另一种体现：在这个数据上"更像真实类别的划分"与"更高的似然/更简洁的模型"并不一致，因为 GMM 在 64 维、每分量样本不足的情况下本来就学不好真实簇形。

## 9. 容易踩的坑

下面这些是原理文档里已经点明、但在编码时仍然极易出错的细节，动手前先读一遍，出错时回来对照。

协方差更新用旧均值是最隐蔽的一个。它不会报错，甚至前几轮似然还在上升，但会在某个时刻开始下降，破坏 EM 的单调性保证。第二个是 `np.cov` 默认除以 $N-1$ 而 EM 的公式除以 $N_k$，手工核对时会发现数值差一个 $\frac{N_k}{N_k-1}$ 的因子。第三个是责任度矩阵的方向：`log_resp` 的形状是 `(N, K)`，沿 `axis=1` 归一化，写错成 `axis=0` 会得到"每个分量在所有样本上的责任度之和为 1"这种量纲完全错误的矩阵，而且因为数值看起来正常不容易发现。第四个是 `np.log(weights)` 在某个 $\pi_k$ 变成 0 时会产生 $-\infty$，进而污染整行，所以 M 步之后要对权重做一个下限截断或检查。第五个是绘制协方差椭圆时需要按特征值大小排序（`np.linalg.eigh` 返回的是升序），否则长轴短轴会画反，图看起来"方向对了但比例不对"。第六个是标准化要按列做且只用一次统计量，如果对 Iris 也做标准化而没意识到它本来量纲相近，会让"是否标准化影响多大"这个结论失去意义，建议在两个数据集上都记录标准化前后的 ARI 作为对照。
